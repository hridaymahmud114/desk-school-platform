Candidate preview A1/A2 validated refs ও A2 authoritative `asOf` response থেকে। Snapshot-এ source token ও used placement dependency রাখুন। Pending candidate selection, attendance, marks ও submit write-এ expected version এবং প্রযোজ্য authoritative dated revision মেলান। Initial acceptance ও reviewed reopen-এর freeze boundary স্কুল অনুমোদন করবে। A8 move M থেকে affected interval-এর version এগোয়, M-এর আগে paper day P-এর token অক্ষত। A8 backdated change যদি P প্রভাবিত করে, stale write reject, scoped diff, candidate review এবং unchanged rows stable ID ধরে reconcile। Accepted historical revisions immutable। A6 current allocation শেষ হলে stale recovery সহ write deny, historical date-এর allocation কেবল provenance। [Design §৩ ও §৫](UI_UX_DESIGN_PLAN.md#exam-and-roster) · [System 4 Implementation §২.১ · CX-07 ও roster consistency](../04-academics-attendance/IMPLEMENTATION_PLAN.md#roster-consistency)

### ৪.২ Policy, deterministic calculation ও submission

Typed policy draft → simulated → approved → effective → superseded। Grade band/year, category weights (মোট ১০০), boundaries/scale, pass rule, rounding stage/mode/precision, effective date, required/missing, absent, exempt ও outlier rule validate করুন। Approved policy-র shape version ও input digest রাখুন। Previous term-এর authorized snapshot-এ একই inputs পুরোনো ও proposed rule দিয়ে চালিয়ে changed pupil/result report করুন। Real baseline pending হলে simulation ও approval evidence pending থাকবে, synthetic simulation দিয়ে flow review চলবে। Simulation report-এর version বদলালে checker আবার দেখবেন। Author থেকে আলাদা approver। A1 term-open boundary-তে applicable policy একবার bind ও lock। Effective version immutable, পরের অনুমোদিত release অতীত snapshot-কে rebind করবে না। [Doc 06 · Policy release](../../06-school-policies-and-integrations.md) · [Blueprint পৃ. ১৮–১৯, ৩০–৩১, ৫৬, ৫৯, ১০১ · GRD-001/004, PLT-011]

### ৪.৪ Approved snapshot, batch release ও correction notice
