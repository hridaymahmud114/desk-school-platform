### System-এর কাজ শেষ হলে CTO কী করবেন

1. **প্রথমে System 1-এর report।** Multi-tenant Platform-এর পুরো assigned MVP কাজ, review ও test শেষ হলে project owner তার completion report CTO-কে দেবেন। Report-এ Feature IDs, PR, target branch, reviewed commit ও test evidence থাকবে। এই ক্রম report চাওয়া ও যাচাইয়ের জন্য। প্রথম তিন Agent নিজ নিজ কাজ পাশাপাশি চালাতে পারবেন।
2. **কাজ যাচাই করবেন।** Report-এর দাবি tracker-এর assigned MVP scope, PR-এর actual diff, CI/test results ও affected system-এর contract-এর সঙ্গে মেলাবেন। Partial feature-এ pilot ও বাকি R1 আলাদা থাকবে। একটি slice merge হলে ওই slice-এর status নথিভুক্ত হবে। পুরো assigned MVP scope-এর evidence মিললে তবেই system-এর MVP কাজ সম্পন্ন ধরা হবে।
3. **Merge বা সংশোধনের ফল জানাবেন।** Checks মিললে CTO verified integration branch-এ প্রস্তুত PR merge করে merge commit ও ফল লিখবেন। Test ব্যর্থ হলে, scope বাকি থাকলে বা conflict মেটাতে source edit লাগলে সংশ্লিষ্ট Agent-কে নির্দিষ্ট finding ফেরত দেবেন। Agent fix ও updated evidence দিলে CTO আবার যাচাই করবেন। Code, schema ও migration সম্পাদনার দায়িত্ব System Agent-এর।
4. **পরের report চাইবেন।** System 1-এর assigned scope যাচাই ও প্রস্তুত PR merge শেষ হলে CTO project owner-এর কাছে **System 2 · Identity and Permissions**-এর report চাইবেন। System 2 একইভাবে শেষ হলে **System 3 · Student Records and Admissions**-এর report চাইবেন। ঘাটতি থাকলে বর্তমান system-এর Agent সংশোধন ও evidence দেবেন।
5. **System 4-এর planning।** Owner চাইলে প্রথম তিন system-এর finishing review-এর পাশাপাশি **Academics and Attendance**-এর পুরো MVP planning হবে। A1/A2 slice 0 হবে প্রথম deliverable। A9 এবং বাকি MVP module-ও একই plan-এ থাকবে। CTO model ও effort জানিয়ে owner-এর নির্দেশে একটি prompt দেবেন। Agent context, design, implementation draft ও একটি combined review prompt দেবেন। **Exams and Results (System 5)** ও **Desk Learn (System 6)**-এর পূর্ণ planning-এর আগে slice 0-এর class ও dated roster contract design review হবে। Coding-এর জন্য owner-এর branch confirmation ও আলাদা নির্দেশ লাগবে। [CTO handoff](CTO-HANDOFF.md#model-and-token)

### Merge ও demo-র ক্রম

1. **Platform প্রথম।** Actual backend checkout, integration base, build/test command ও owner যাচাই করে project owner Doc 02-এর ছোট branch খুলবেন। C2/C1/C9-এর যাচাইকৃত context ও entitlement interface আগে merge হবে। V01/V18-এর এই slice-এর evidence ও consumer contract review লাগবে।
2. **Identity দ্বিতীয়।** Updated base নিয়ে C3-এর server-side action, campus ও child-right checks মিলিয়ে merge। Students code বা UI-তে Registrar-এর role নতুন করে সংজ্ঞা দিতে হবে না। **দুই ভাগে merge (CX-01, owner সিদ্ধান্ত ২৬ নভেম্বর ২০২৬)।** **1a:** custody restriction ও audit বাদে বাকি কাজ, Platform-এর প্রথম slice merge হলেই merge। **1b:** custody restriction ও audit evidence, Platform-এর PLT-006/007/013 merge হওয়ার পরে, **G1 staging-এর আগে বাধ্যতামূলক**।
3. **A1/A2 slice 0 (OD-13, owner সিদ্ধান্ত ২৬ নভেম্বর ২০২৬)।** System 4-এর পূর্ণ MVP plan-এ প্রথম deliverable ন্যূনতম A1/A2 contract। এর কাজ হলো class/section reference এবং A8-এর dated placement থেকে roster read। System 1–3-এর finishing review-এর পাশাপাশি planning হতে পারে। Owner coding-এর অনুমতি দিলে slice 0 পাশাপাশি তৈরি হতে পারে, Identity 1a-র পরে ও Students-এর আগে merge হবে। Merge ক্রম: **Platform → Identity 1a → A1/A2 slice 0 → Students**। Students নিজস্ব A1/A2 stub বানাবে না; port-এর পেছনের fake শুধু test-এর জন্য।
4. **Students।** Updated base-এ real Platform ও Identity দিয়ে দুই school-এর পরীক্ষা। A1/A2 owner-এর সঙ্গে যাচাইকৃত class reference দিয়ে import → guardian link → প্রথম placement → effective roster মেলাতে হবে। Fixture দিয়ে শুরু করা planning-এর evidence আর real integration run-এর evidence আলাদা থাকবে।
5. **প্রথম school-day demo।** A9-এর roster, offline sync ও correction যুক্ত হলে C4/C5-এ ঠিক guardian-এর day view ও notice মিলবে। C8 adapter নিজের sandbox ও consumer checks পেরোলে সংশ্লিষ্ট SMS/payment flow-এর সঙ্গে যুক্ত হবে। Provider পেতে দেরি হলে তার evidence pending থাকবে।
6. **পরের merge-গুলো dependency ধরে।** Results, Fees ও Desk Learn নিজেদের domain flow আলাদা review পাবে। Selected marks integration-এর আগে Learn ও Results, payment-এর আগে Fees ও C8, আর report card-এর আগে Results ও Apps-এর contract মিলবে। School Operations-এর প্রথম merge R2। Branch merge, G0 Foundation demo, G1 staging ও live pilot acceptance প্রত্যেকটির আলাদা evidence আছে। [Doc 02](../02-mvp-release-and-branch-plan.md) · [Doc 07](../07-qa-pilot-and-acceptance.md)
